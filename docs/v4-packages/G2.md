# Package G2: GDAC source wiring (integrator)

## What was wired

- Admission: `Repository.admit(..., input_kind="gdac")` stores `policy_versions("gdac-core-v1")`
  (equal to `gdac.VERSIONS`); every other input kind keeps the Argovis versions.
  `validate_replay(..., source_contract=...)` compares against that contract (default Argovis).
  `argovis.source_of(versions)` maps versions to `"gdac"`/`"argovis"` (mirror of `app.run_source`).
- `process_ticket` (`workers/.../ingestion.py`): reads the run input first, checks the run's
  policy against the contract of its own source (`unsupported_policy_versions` otherwise), builds
  `GdacSource(repository, store, authority, inputs["descriptor"], deadline=..., application_commit=...,
  require_existing=...)` for `kind == "gdac"`. The Argovis key is never loaded for gdac.
- `Processor` reads the input kind once in `__init__` (`self.source_name`) and routes `map()` to
  `gdac_map_profile(doc, budget, self.metadata(doc))`. The source name is also passed to
  `identities`, `identities_batch` (as `source=`), `slot_state(source=)` and `ProfileSpool(source)`.
- Source-aware keys in Python (default `"argovis"`, so Argovis behaviour and goldens are unchanged):
  `planning.MAPPINGS`, `workflow.slot_key/owner_slot(..., source)`, `StoredState.slot_of(source)`,
  `coverage.resolve(..., source=)`, `Repository.catalogue_snapshot(..., source=)`,
  `catalogue.select_active_partitions(..., source=)`, `repository.OWNER_FUNCTIONS`.
  `compact`, `compactable_slots`, `compact_slots` (CLI) are key-driven and needed no change
  (verified for a `gdac/core/...` key in the end-to-end probe).
- CLI: `ingest --source {argovis,gdac}` (default argovis). The input group is no longer
  argparse-required: argovis without `--fixture-index/--replay-run/--live-opt-in` gives
  `missing_ingest_input`; gdac with any of them gives `unsupported_gdac_input`. gdac calls
  `gdac.prepare_cache(--gdac-cache or <private>/gdac-cache, interval, monotonic()+execution_seconds)`
  and admits `input_kind="gdac"` with the returned descriptor. `fixture_descriptor` unchanged.
- `scripts/stage1_acceptance_runtime.py`: `ingest --source {argovis,gdac}` (default argovis) and
  `--gdac-cache`; gdac passes `--source gdac` instead of `--live-opt-in`/`--replay-run`.
  `MIGRATION_HEAD` is now `0015_gdac_wiring`.

## Category classification

Added to `FAILURES` (state `failed`): `gdac_file_size_limit` (raised in `fetch_file`, download side),
`gdac_index_changed`, `invalid_gdac_descriptor`, `unapproved_cache_path`, `invalid_request_parameters`,
`invalid_request_role` (run/environment configuration, not data). Already `FAILURES` and reused by
the download path: `http_retry_exhausted` (404 included), `http_retry_deadline`,
`upstream_transport_failure`, `io_deadline`. Quarantine (default): `invalid_netcdf`, `netcdf_size_limit`,
`unsupported_netcdf_packing`, `invalid_index_line`, `invalid_gzip` and every mapper rejection.
`SPLITTABLE` is unchanged (`profile_count_limit`, `decompressed_size_limit` split as for Argovis);
`incomplete_inventory` is unchanged. Not changed because the same names exist for Argovis in
`transport.py` and moving them would change Argovis behaviour: `truncated_http_body`,
`upstream_redirect_rejected`, `upstream_dns_unsafe/empty`, `unsupported_*_encoding`,
`unapproved_upstream_endpoint`, `invalid_content_length`, `ambiguous_http_framing` stay quarantine.
`invalid_netcdf` raised while validating a freshly downloaded file also quarantines (arguably a
transport fault; decide if wanted).

## Migration 0015 (`infra/migrations/versions/0015_gdac_wiring.{py,sql}`, `down_revision = "0014_gdac_source"`)

- New `app.run_source(jsonb)` (`'gdac'` when `mapping = 'gdac-core-v1'`, else `'argovis'`) and
  `app.profile_slot(source, time, lon, lat)`; index `argo_profile_gdac_slot_idx` (partial, source gdac);
  EXECUTE for `floatchat_ingestor` on `gdac_owner_slot`, `run_source`, `profile_slot`.
- `app.admit_run`: 0010 body with scope row, overlap record and scope update per source of the
  versions (Argovis and gdac runs are separate scopes and may run concurrently).
- `app.ensure_slot`: owner slot of the run's source.
- `app.commit_publication`: 0013 body; changes only: source of the candidate = `science->>'source'`
  (must equal the run source, else `scientific_hash_mismatch`), accepted mapping is
  `argovis-core-v1`/`gdac-core-v1` by source, `argo_float`/`argo_profile` lookups and inserts and
  the advisory lock namespace use that source, slots via `app.profile_slot`, receipt counts via the
  source's own owner function (EXECUTE, so each population uses its own index).
- `app.audit_slot_manifest` (now plpgsql, same signature and result) and
  `app.report_metrics_snapshot` (`selected_profiles_by_slot` via `profile_slot`) are source-aware.
  `app.owner_slot`, the 0011 index, and every category are untouched.

## Left for the integrator / open

- Metadata landings (item 6) are NOT skipped: each platform still costs a recorded attempt and
  manifest; skipping touches `land()`, `reload_landing()`, `map()` and the `raw_roles` accounting.
- `parquet.schema()` metadata still says `mapping_version=argovis-core-v1` for gdac parts (changing it
  alters the schema hash and goldens). Parts are otherwise valid; reader code must not use that field
  as the source.
- GDAC `--replay-run` is out of scope (replay would build `RecordedSource`).
- Reporting text (`report_metrics_snapshot` attribution) still names Argovis as the provider.
- `Repository.stored()` and other scans over `app.argo_profile` that are not source-filtered were
  not touched.
- `prepare_cache` runs in the CLI process before admission with `execution_seconds` as its deadline;
  a lease longer than the longest single download is still the operator's concern (G.md item 8).
- Process order in `process_ticket`: `missing_input_descriptor` is now checked before the policy check.
